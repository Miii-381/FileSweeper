# Android MVP 使用与构建

Android 版沿用 Tauri 2、React 和 Rust，文件任务与原生播放器通过 Kotlin 插件接入 Android 生命周期。首版支持 Android 11（API 30）及以上，当前构建目标为 ARM64。应用以手机内置共享存储为工作范围。

## 使用

1. 安装 APK，首次打开时授予“所有文件访问权限”。Android 自身限制的目录仍可能无法访问。
2. 在下方目录中点按文件预览，长按文件执行重命名、复制、移动、删除或外部打开。多选位于文件工具栏的更多入口。
3. 拖动分隔条调整上下空间。预览可收起；收起后选择文件不会自动展开。全屏模式允许跟随系统旋转。
   图片默认居中并完整适应实际窗格，窗格尺寸变化和旋转后重新适应。PDF 双指手势只缩放文档，单指用于滚动，应用界面本身保持固定倍率。
4. 视频画面使用无内置控件的原生播放器，播放、暂停、进度和静音位于画面下方的独立控制条。视频和音频均可在预览区域横向拖动快进、快退，松手提交；取消手势不跳转。长按约 450 毫秒后临时倍速播放，松手恢复原来的速度与播放／暂停状态。
5. “设置 → 播放与浏览 → 切换文件自动播放”默认开启，可关闭并保存。收起、后台、锁屏以及打开面板时暂停；返回预览需要手动继续。
6. 首次文件任务按系统提示允许通知，以显示后台进度与取消入口。拒绝通知不等于文件任务未启动。
   复制按已复制字节与总字节显示百分比，目录复制先统计大小；同卷移动按完成项数显示。全部任务结束（包括取消或失败）后撤销进度通知，结果保留在任务面板中。
7. 从“位置 → 回收站”进入回收站。点选单项或长按进入多选，也可用工具栏进入多选、全选搜索结果；底部支持批量恢复、恢复到指定目录和彻底删除。列表／网格、搜索和勾选样式与文件区一致，顶部持续显示回收站提示。
   “全部删除”直接对整个回收站发起清空确认，不受搜索条件影响。确认页列出数量、名称和原位置，明确提示无法恢复；取消后保留勾选。正在处理的项目禁止重复提交，任务结束后自动刷新。
8. “位置 → 喜好路径”支持添加、自定义名称、编辑与移除；可填写路径或浏览选择目录。移除喜好路径仅删除书签。
9. 开启“记忆焦点与浏览位置”后，各目录分别保存所选文件、排序、列表／网格和滚动位置；切换目录或重新启动时恢复。顶栏的焦点跳转按钮会清除搜索条件并定位当前文件；删除按钮按回收站设置处理当前焦点文件，完成后选择相邻文件。
10. 设置使用独立分组卡片，展开标题与内容区有明确边界。“文件任务”是设置的二级页面，返回按钮、关闭按钮和系统返回均回到设置，保留分组展开状态与滚动位置。任务显示具体文件名、来源／目标、逐项状态和失败原因；失败后可“重新执行”，中断或取消后可“继续未完成项”，已完成项目不会重复执行。回收站任务记录原文件名，避免把内部存储名 `content` 当作文件名。

## 手机设置

| 设置组 | 已接入的设置 |
| --- | --- |
| 外观与背景 | 跟随系统、深浅色、五种强调色、系统选择器导入背景、当前图片设为背景、不透明度、模糊 |
| 播放与浏览 | 自动播放、长按倍速（1.25／1.5／2／3 倍，默认 2 倍）、静音、预览音量、记忆目录与焦点/排序/视图/滚动位置、隐藏文件、显示 `.nomedia` 中的媒体 |
| 预览与性能 | 代码主题、中英文字体、代码语言映射、四类扩展名、图片大小/像素上限、缩略图缓存上限与视频取帧位置 |
| 文件安全与缓存 | 回收站开关、手动清理缩略图、回收站手动恢复与彻底删除 |

设置由原生端校验并持久保存。列表和网格中的文件夹图标、图标底色，以及位置面板和目录选择器中的文件夹图标均跟随主题色。`.nomedia` 同时检查当前目录和共享存储范围内的祖先目录；关闭“显示 .nomedia 中的媒体”时隐藏图片、视频和音频，文件夹、文本和 PDF 仍可浏览。背景导入保存一份私有副本，之后移动源图片不影响背景；移除背景仅取消显示。

桌面三栏布局、目录树、桌面列表列宽、FFmpeg 进程并发参数没有加入手机设置。移动端不分发 FFmpeg；实际媒体播放能力由设备解码器决定，失败时可使用其他应用打开。文本读取预算为 4 MiB，背景导入上限为 32 MiB / 64 MP，图片预览限制可配置。

## 文件任务与回收站

- 文件任务先保存私有任务记录，再执行变更；关键阶段立即写入，复制进度节流保存。界面与通知都读取原生任务状态。
- 界面也会跟踪脚本直接发起的原生文件任务，完成后刷新目录并更新焦点。原生媒体关闭时清空播放项目，尺寸更新和关闭回调按文件校验，避免已删除或已切换文件的旧画面残留。
- 回收站在共享存储 `.FileSweeperTrash` 下逐项执行同卷移动，通过原子的“不覆盖已有目标”提交，避免整批复制暂存。元数据仍需要少量可用空间，完全满盘时不能保证回收成功。
- 复制使用任务专属临时目标，完成后无覆盖提交。回收站恢复遇到名称冲突会选择可用名称。
- 前台服务负责后台任务与通知，媒体不会作为后台音乐服务运行。系统终止后，任务记录供再次启动时核对并手动继续；不自动恢复破坏性操作。
- MVP 任务面板展示最近 30 项，终态记录保留在磁盘，为后续历史功能提供基础。
- 回收站批量恢复、彻底删除和清空均保存为一个多项任务，后台逐项执行。批量恢复会为同名项目预留不同的目标名称；任一条目校验失败时不会创建或开始该批任务。执行期间失败则保留已完成结果，剩余项目可从任务面板核对后继续。

初始方案倾向复用桌面 Rust 执行器。MVP 实施后，移动端执行器直接放在 Kotlin 服务侧，避免后台任务依赖 WebView 或同步跨层回调；Rust 仅提供预览流和无覆盖移动的 JNI 原语。未额外引入数据库、通用调度框架或多存储抽象。

## 构建

依赖 Node.js、Rust、JDK 17、Android SDK Platform 36、Android Build Tools、Android NDK，以及 `aarch64-linux-android` Rust target。SDK 和 JDK 路径使用本机环境变量，不写入仓库。

```powershell
chcp 65001 > $null
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
[Console]::InputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
$PSDefaultParameterValues['*:Encoding'] = 'UTF8'
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-17'
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
rustup target add aarch64-linux-android
npm install
npm run android:build
```

输出：`src-tauri/gen/android/app/build/outputs/apk/arm64/debug/app-arm64-debug.apk`。这是调试签名的测试包。构建脚本默认关闭开发调试符号与增量缓存，以控制磁盘占用；Windows 未开启符号链接权限时，脚本复制本次编译的原生库继续 Gradle 打包。

手机连接并授权 USB 调试后，可执行 `adb install -r <APK路径>`。`npm run android:dev` 用于开发调试。

## 验证与日志

`npm run test:unit` 覆盖前端逻辑与播放行为。`node scripts/android-smoke.mjs` 对已安装的调试 APK 执行真机冒烟测试：脚本在下载目录创建独立的 `FileSweeper-MVP-Test-时间戳` 样本目录，通过 WebView 调试接口操作应用。需要手机解锁并保持应用前台；通知权限仍通过正常系统授权流程处理。脚本若检测到本机已有 FFmpeg，仅用它生成视频样本，不下载或打包该工具。

真机结果和截图写到本机 `artifacts/android`，不纳入版本控制。测试保留样本目录便于手工复核。

设置 `$env:ANDROID_SMOKE_TASKS = 'true'` 后，脚本额外创建 96 MiB 样本，验证通知发布、应用退到后台后的复制、强制停止后的手动恢复及 SHA-256 一致性，再删除该次创建的大文件。该模式会短暂切换到桌面并重新启动 FileSweeper。

2026-10-31 在已连接的 2304FPN6DC（Android 16 / ARM64）上通过 23 项真机检查；前端通过 49 项测试，Android 调试构建成功，Lint 为 0 错误、35 警告、1 提示。已验证外置播放控制、自动播放开关、祖先 `.nomedia` 过滤、扩展名分类、背景私有副本、复制/移动/回收与恢复；回收前后 inode 保持一致。系统文件选择器的交互路径和不同厂商设备仍需手工复核。

同日修复图片画布高度、居中适应、PDF 手势误缩放应用及进度通知残留问题后，前端测试增至 51 项。`node scripts/android-regressions.mjs` 提供对应真机回归：测量图片中心与适应倍率，发送真实 WebView 双指事件并检查 `visualViewport.scale`，观察系统实际发布的复制/移动通知，覆盖完成、取消和冲突失败后的撤销。通知回归在独立样本目录创建约 128 MiB 文件并在通过后清理；结果写入 `artifacts/android/regression-results.json`。仅验证手势时可设置 `$env:ANDROID_REGRESSION_GESTURES_ONLY = 'true'`。

回收站更新后，前端共 55 项测试通过。`node scripts/android-trash-smoke.mjs` 验证批量回收、多选删除与取消、列表／网格勾选、同名文件恢复，以及不受搜索条件影响的清空确认；结果写入 `artifacts/android/trash-results.json`，截图保存在同目录。脚本仅操作独立样本；若手机已有其他回收项目，只验证清空确认与取消，不执行清空，并核对既有条目保持存在。

原生日志位于应用私有目录 `files/logs/mobile.log`，超过 2 MiB 轮转；任务记录位于 `files/tasks`。调试包可用 `adb shell run-as com.ayanami.filesweeper cat files/logs/mobile.log` 读取。日志包含模块、时间、文件任务阶段和异常，预览、设置、后台服务、外部打开均有记录。

导航与媒体手势回归使用 `node scripts/android-navigation-smoke.mjs`，需要本机 FFmpeg 和已安装的 Android instrumentation 测试包。先在生成的 Android 工程中执行 `gradlew.bat assembleArm64DebugAndroidTest -x rustBuildArm64Debug`，再安装 `app/build/outputs/apk/androidTest/arm64/debug/app-arm64-debug-androidTest.apk`。脚本覆盖喜好路径、按目录焦点记忆、进程重启、顶栏删除与任务入口；手势部分在手机上向本应用的原生视图分发触摸事件，验证视频／音频快进快退、取消与长按倍速。脚本在独立目录生成样本，结束后清理样本及其回收项，并还原原有设置与浏览记忆。测试 APK 仅用于验证，无需向用户分发。

2026-11-01 上述导航回归共 8 项通过，包括脚本直接重命名、删除视频后的焦点同步，以及旧尺寸回调不能恢复已清除画面。前端共 61 项测试、Rust 共 59 项测试通过；Rust 格式检查与 Clippy 通过，Android Lint 为 0 错误、33 警告、1 提示。Windows 构建清单改为由链接器统一嵌入，避免拆分库入口后测试程序缺少 Common Controls 或二进制重复嵌入清单。

设置与任务页面优化后，前端共 63 项测试通过，导航回归增至 9 项。新增设备内测试先执行一个真实的两文件复制任务，令第一项成功、第二项因目标冲突失败；再通过任务页的“重新执行”按钮完成第二项，核对第一项 inode 保持不变、任务完成数为 2，失败原因已清除。同步验证二级页面的返回路径、设置状态保留、中文文件名与失败详情，并检查真机截图。Android 构建及 Lint 通过，仍为 0 错误、33 警告、1 提示。

超低剩余空间、六小时后台时限、大目录压力及多种厂商设备仍需专项验收，冒烟测试不能替代这些边界验证。
